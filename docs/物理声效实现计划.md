# 唱片机物理声效 —— 真正的实现计划（v2）

> 现状结论（诚实版）：0.10~0.12 那套是**自研 PCM DSP**（一阶低通 + 玩具 Schroeder + 只看"隔没隔东西"），
> **上限就在那里** —— 延迟来自"参数跟着音频块走"，没有材质、没有反射、没有方向。
> 想要 Sound Physics Remastered 那种效果，必须换成**和它同一层的机制：OpenAL EFX**。

## 目标

- 效果层级 = 真实混响（EFX EAXReverb）+ 材质相关遮挡 + 随空间变化 + **延迟 ≤ 1 tick**
- **纯客户端**；只作用于**我们自己的音源**；原版唱片与其它声音**完全不受影响**
- 任何失败**自动回退**到现在这套 DSP（出声永远优先于效果）

## 三层架构

### 1) 采集层（主线程，每 tick）
- **遮挡射线（沿连线）**：从耳朵到唱片机分段取样（每 ~0.5 格，最多 64 段），
  每命中一个方块就查**材质表**，累加 `occlusionAcc` 与平均 `reflectivity`
- **混响射线（向外）**：从唱片机均匀发射 32~64 条，每条最多 4 次反弹；
  记录命中距离、面法线、材质反射率 → 累加成 **4 个延迟带** + **逐层反射率**
- 射线预算上限（可配）：默认 ≤ 256 条/秒
- 全部在主线程做（world 只在主线程安全）→ 用 `IdentityHashMap` 缓存 BlockState 参数

### 2) 参数层（每 tick）
- 由采集结果算出（与 SPR 同一组量）：
  `directCutoff`（0..1）、`directGain = directCutoff^0.1`、
  `sendGain[0..3]`、`sendCutoff[0..3]`
- **按 tick 做时间常数平滑（约 0.15 s）** —— 这一步就是解决"延迟高"的关键：
  参数不再等音频块，主线程算完立刻写进声源

### 3) 应用层（每 tick，主线程）
- 用 `EXTEfx`（LWJGL 自带，Minecraft 已依赖）给**已捕获的我们的 source**：
  - `alSourcei(src, AL_DIRECT_FILTER, lowpass)` + `AL_LOWPASS_GAINHF = directCutoff`
  - 4 个 aux effect slot（EAXReverb）；`alSource3i(src, AL_AUXILIARY_SEND_FILTER, slot[i], i, filter[i])`
  - slot 参数只在变化超过阈值时更新（避免每 tick 重算）
- EFX 初始化失败 / `alcIsExtensionPresent(ALC_EXT_EFX)` 为假 → **回退 DSP**，并打一条日志

## 材质表（自己推导，MIT，不抄它的配置）

每个方块给一个三元组 `(occlusion, reflectivity, absorption)`：
- **方块声音组**（`state.getSoundGroup()`）：石/木/羊毛/玻璃/金属… → 基础吸声
- **是否完整方块**（`state.isOpaqueFullCube`）：不完整方块按 `non_full_block_occlusion_factor` 打折
- **硬度 / 是否为液体 / 是否金属** 做微调
- 结果缓存进 `IdentityHashMap<BlockState, 参数>`

## 其它细节
- **水下**：`player.isSubmergedInWater()` → 直通再乘 0.1
- **空气吸收**：按距离对 `directCutoff` 再衰减（高频先没）
- **开阔度修正**：无阻挡射线比例 → `cutoff = max(sqrt(openness) * 0.2, cutoff)`（这条继续用，方向对）

## 性能硬指标
- 主线程：每 tick ≤ 2 ms（用 `performance_logging` 打耗时）
- 音频线程：**不参与**（EFX 由引擎/驱动处理）→ 从根上消除块级延迟

### 实现与计划的差异（诚实记录）

1. **遮挡不做"每 0.5 格取样"**，改成 **DDA 体素遍历**（`RayWalk`）。原因：取样法既要靠 epsilon
   续射，又会把同一个方块算两遍；DDA 一次拿到"穿过哪些格子 + 入射面法线"，更准也更快。
2. **`ALC_MAX_AUXILIARY_SENDS` 默认只有 2**（用独立 LWJGL 探针实测），所以写了
   `SoundEngineMixin` 请求 4 个发送 —— 这一步计划里没写，但不做就只有 2 段混响。
   它有安全阀（异常/失败都退回原样调用）。
3. **M4 先做 1 个 slot**（4 个延迟带的能量先合并送 slot 0），M5 才拆成 4 段；与计划一致。
4. **混响段数少的自动降级**：EFX 段数不足时把后段折回前段，不丢能量。

- **取证优先**：`physicsSoundDebug=true` 时日志里会出现
  `材质探针: <方块> → 遮挡/反射率/吸声（来源=…）`（每轮最多 6 条、最多 1 秒一次），

## 调参记录（0.12.6 —— 改了哪些常数、为什么）

> 触发：用户实测 0.12.5「有效果 ✓，但没那么激进，有些场景听不出来 ✗」，
> 追加要求「**隔墙变闷必须明显到一耳能听出来**，优先级高于混响」。
> 本轮**只调参 + 加诊断**：没有新增/删除 mixin，没有动 EFX 架构与调用链。

### 先定位"为什么不够明显"（三个原因，都能指到代码）

1. **开阔度修正在最后一步把遮挡顶了回去**（0.12.5 `Acoustics.evaluate` 里的
   `cutoffWithShared = max(sqrt(avgShared)*0.2, cutoffNoAir)`，没有门槛）：
   站在开阔房间隔一层石头墙 → `avgShared≈0.9` → 下限 `0.19` 直接把
   `exp(-1.0*3)=0.0498` 顶成 **0.1897**。用户听到的"0.2~0.3"就是这个数。
   **而且这个下限与墙厚无关**：一层石头、两层石头、深板岩，下发值全是 0.1897。
2. **8 条偏移射线取最小值**：一条缝 → `occ=0` → `cutoff=1.0` → 滤波器等于没挂
   —— 这就是"有些场景完全听不出来"。
3. `gain = cutoff^0.1`：`0.0498^0.1 = 0.741`，隔墙总音量只掉 2.5 dB，
   感知到的"闷"几乎全来自高频那一段（用户要求"总增益也跟着降一点"）。

### 一处有意的副作用（诚实记录）

按上面的默认值，`max(0.2*sqrt(shared)*(1-occ/0.6), exp(-occ*4.5))` 里的**开阔度那一项永远赢不了**
—— 也就是计划里那条"开阔度修正"（同一片开阔空间声音能绕过来 → 直通不该被压死）
**对直通截止实际上停用了**。这是有意的：它正是把"隔一层石头墙 0.05"顶回 0.19 的元凶。
- 代码形状保留：把 `physicsAbsorption` 调回 2~3，它就会重新起作用（用户可自测）。
- `SharedAirspace` 仍在混响侧生效（4 个延迟带权重 `w0..w3`、DSP 兜底的 `openness`），
  "开阔空间尾巴长、小房间短促"这条听感不受影响。
- 详见 [CHANGELOG-内部.md](CHANGELOG-内部.md) 的 0.12.6 一节。

### "从最弱到最强"的旋钮顺序（用户自己微调用）

| 想改什么 | 动哪个 | 方向 | 副作用 |
|---|---|---|---|
| 整体变强/变弱（推荐先用这个） | `强度` (`physicsSoundLevel`) | 0（关）→ 2 最激进 | 同时放大闷度与余响；2.0 可能"闷到听不清内容" |
| 只把"隔墙闷"调狠 | `隔墙闷度 k` (`physicsAbsorption`) | 2.0（几乎不闷）→ 9.0（到下限） | 太大时所有材质都会撞到截止下限 0.005，材质差异被吃掉 |
| 门缝/拐角透不透 | `漏音通路数` (`physicsOcclusionPaths`) | 1（最慈悲，接近 0.12.5）→ 9（最严） | 调大后站在门口也可能发闷 |
| 想彻底当墙 | `严格遮挡` (`physicsStrictOcclusion`) | 开 | 连门缝都不透，最容易"听不出来有变化"的反面 |
| 余响多少 | `强度` + `发送基准 SEND_BOOST` | 1.0 → 1.6（默认）→ 更大 | 太大时会"糊" |
| 材质对比度 | `BlockAcoustics.baseFor` 各档遮挡 | 拉开差值 | 需要重新构建 |

## 0.12.9 修 bug 记录（混响被掐死 + 预算砍直通 → 已定位并修）

> 现场：0.12.8 装进游戏后「还是没有音效，直接整体全部效果都没了」。
> 日志一眼可辨：`sendCutoff=[0.001, 0.001, 0.001, 0.001]`（混响 4 路自己的低通 ≈ 静音）、
> `直通增益=0.153` 又被能量预算乘 0.68（真正下发 0.104）。
> 本轮**只改两个数值公式 + 加一组可听下限 + 加两个日志字段**，没有动 EFX 架构。

| 项 | 旧（0.12.8，公式在 `Acoustics.traceReverb` / `EfxEngine.applyToSource`） | 新（0.12.9，抽成纯函数） |
|---|---|---|
| 混响发送高频 | `exp(-occ×k)`（k=4.5，直通那条链路的常数）→ occ=2.1 时 **7.9e-5** | `(0.20+0.80×exp(-occ×0.5)) × (0.60+0.40×反射率)`，**硬下限 0.20** |
| 能量预算 | `total = 直通 + Σ发送增益`（低通 0.001 的空发送也占满预算）→ 预算 **0.683** | `E = Σ(发送增益×发送高频×混响增益)`，`directBudget = max(1/total, 0.5)` → 预算 **1.000（不削）** |
| 直通下限 | 无（两层石头墙 GAIN 0.153 / GAINHF 0.006） | `MIN_AUDIBLE_DIRECT_GAIN = 0.25`、`MIN_AUDIBLE_DIRECT_CUTOFF = 0.02` |
| 日志 | — | 新增 `能量预算(直通倍率)=? 有效发送能量=?`；真削时多一行 `物理声效·能量预算: …` |
| 自检 | `AcousticsMath` / `OcclusionWalkTest` | 新增 `PhysicsParamsTest`（**直接调生产代码的三个纯函数**，输入=真实日志三行）；`AcousticsMath` 扩展两节 |

**用真实日志输入复算的结果**（两层石头墙那一行）：
`直通 GAINHF 0.0050→0.0200`、`GAIN 0.1511→0.2500`、`sendCutoff 0.0001→0.371~0.382`、
`预算 0.683→1.000`、**实际下发直通增益 0.1032→0.2500（+7.7 dB）**、送进混音器的湿声能量 `~0 → 0.16`。
通畅那一行预算 `0.4279→0.7356`（原来在开阔地也白掉 -7.4 dB）。

**诚实的代价（详见 [CHANGELOG-内部.md](CHANGELOG-内部.md) 0.12.9 的"已知限制"）**：
"一层石头"与"两层石头"的高频都被抬到 0.02（不再有区别，总增益仍有 0.407/0.250 的区别）；
极厚墙的总增益被抬到 0.25；混响发送高频没有按反射次数累乘；**听感必须由用户实测确认**。

## 0.12.8 修 bug 记录（0.12.7 遮挡恒为 0 → 已修 + 补上累加路径的离线自检）

> 现场：0.12.7 装进游戏后「遮挡完全不生效、声效全无」，日志里 `遮挡累积=0.000`（各距离恒为 0），
> 但同一轮里 `材质探针: oak_door → 0.44` 说明材质表是好的、EFX 也正常。
> 本轮**只修遮挡累加 + 补自检**，不动 EFX 架构、不动混响。

### 根因与排除过程

1. **先排除"坐标约定"**：怀疑 `VoxelShape.raycast(from, to, pos)` 要局部坐标。
   - 反编译字节码证明：它内部把 `pos` 从坐标里**减掉**（局部化）做快判，再交给
     `Box.raycast(Iterable, from, to, pos)`，后者对每个盒子 **`box.offset(pos)`** 之后才与世界坐标求交
     ⇒ **要世界坐标**；
   - 探针实测同样结论（世界坐标 → 命中；减掉 pos → null）。
   ⇒ **0.12.7 的调用语义是对的**，问题在"只依赖引擎单一分支、且没有兜底"：
   该分支一旦返回 null，整条遮挡链路**静默变成"什么都不挡"**。
2. **`通透通路=0/8` 是个误导读数**：`occMain=0` 时 `evaluate` 根本不算偏移射线，这个 0 只是初值。

### 改法（"两条腿走路"，不再可能静默归零）

| 项 | 旧 | 新 |
|---|---|---|
| 几何判定 | 只调 `VoxelShape.raycast` | **满格体素直接判挡**（石头/玻璃/原木/木板/关着的门，不调用求交）；不满格/多盒（楼梯/栅栏/半砖/活板门/玻璃板）才逐盒精确求交；盒子列表拿不到才退回引擎求交 |
| 起点在材料内 | 被当成"不挡" | `box.contains(from)` 也算挡 |

## 0.12.7 修 bug 记录（门关/门开听不出差别 → 已定位并修）

> 触发：用户实测 0.12.6 反馈「**门关上时候和开着时候的遮挡一样几乎没有**」。
> 本轮**只改遮挡链路 + 顺手的稳健性加固**，没有新增/删除 mixin，没有动 EFX 架构。

### 根因（都在代码里，逐条给出实际公式）

1. **放宽（漏音）规则把主射线的遮挡砍掉 85%** —— `Acoustics.evaluate`：
   ```java
   double relax = MAX_RELAX * Math.min(1.0, openPaths / (double) need); // 0.85 × min(1, 通路/3)
   occ = occMain * (1.0 - relax);   // 乘的是 (1-放宽)，位置在 MAX_OCC clamp 之后、exp(-occ*k) 之前
   ```
   `physicsOcclusionPaths` 默认 3 ⇒ **8 条偏移射线里 3 条通透就只剩 15% 遮挡**。
   而偏移射线是"整条线平移"：擦墙边、过门口、过墙角都会变成"通透"，
   所以**一扇关着的门旁边很容易凑够 3 条** ⇒ 0.22 → 0.033 ⇒ 截止 0.86（-1.3 dB）= 听感上"没效果"。
2. **关着的门本身只算 0.22**：木门 `isOpaque()=false`（×0.8）且 `isOpaqueFullCube()=false`（×0.5），
   0.55 → 0.22 ⇒ 截止 0.372（-8.6 dB），只是"稍微暗一点"。
3. **几何判定基于"方块类型"而不是"射线实际有没有被挡住"**：DDA 只判"这一格有没有碰撞体积"，
   再靠 `isOpaqueFullCube` 打对折补偿缝隙 —— 于是关着的门被当成"一条缝"，
   而楼梯/栅栏的缝反而被整格当成实心。

> 顺带回答"开着的门"：碰撞形状为空 ⇒ 本来就算 0，这一条 0.12.6 就是对的；
> 问题全在"关着的门"被削得太狠，两边一凑就"一样"了。

### 改法（保守且可预期）

| 项 | 旧 | 新 |
|---|---|---|
| 放宽门槛 | 3/8（配置 `physicsOcclusionPaths`=3） | **6/8**（默认；范围 1~8） |
| 放宽幅度 | 写死 0.85 | **新配置 `physicsOcclusionRelax` = 0.40**（0~0.60，最多削四成） |
| 放宽条件 | 过门槛即按比例放宽 | **达不到门槛一分不放宽**；过门槛后按 `(通路-门槛+1)/(8-门槛+1)` 线性给到上限 |
| 是否累加遮挡 | 有碰撞体积就算 | **射线与碰撞形状精确求交**（`VoxelShape.raycast`）才算 |
| 非完整方块 | × 0.5 几何打折 | **删除**（几何已精确判定） |
| 玻璃基础遮挡 | 0.50（实际 0.20） | **0.25**（实际仍 0.20，听感不变） |
| 配置版本 | 5 | 6（`physicsOcclusionPaths ≤ 3` 时迁到 6） |

**结果**（`tools/AcousticsMath.java` 实跑）：门关 **0.44 → 截止 0.138（-17.2 dB）**、
门开 **0 → 1.000**、石头 0.011、玻璃 0.4066、木板 0.0842；门关/门开的高频差距 **8.6 dB → 17.2 dB**。

### 顺手加固（刺声：不改架构，只去台阶）

- EFX **接线只做一次**（换声源时），播放期间只改数值；关开关先平滑到直通再摘；
- 直通 + Σ发送做**能量预算**（`budget = min(1, 1/(直通+Σ发送))`），避免相加削顶；
- 参数写入**每 3 刻一次**、阈值 0.008 → 0.02；`AL_POSITION` 同样限频（本来已按 0.15s 平滑）；
- DSP 兜底**链路全程接通**（不再清滤波器状态 —— 那会产生一个阶跃）；
- 混响效果器**只在 init 绑一次**到 slot，之后只改参数；
- 新增 `物理声效·参数阶跃:` 诊断日志（超阈值时打旧值/新值，限频 1 秒）。

## 教训（本项目已经踩过的）
1. 带"上次时间戳"的限频代码，初值**必须** `Long.MIN_VALUE / 2` 或 `0`，否则减法溢出 → 永远 return
2. 平滑系数必须**按时间**算，不能按"调用次数"（音频块大小会变）
3. 改配置/JSON 文件**禁止**用 `-replace` 拼字符串（曾把 mixin 配置写空）
4. 效果类问题先开**调试日志/调试渲染**观测，再动手
