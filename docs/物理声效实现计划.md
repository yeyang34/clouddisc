# 唱片机物理声效 —— 真正的实现计划（v2）

> 现状结论（诚实版）：0.10~0.12 那套是**自研 PCM DSP**（一阶低通 + 玩具 Schroeder + 只看"隔没隔东西"），
> **上限就在那里** —— 延迟来自"参数跟着音频块走"，没有材质、没有反射、没有方向。
> 想要 Sound Physics Remastered 那种效果，必须换成**和它同一层的机制：OpenAL EFX**。

## 目标

- 效果层级 = 真实混响（EFX EAXReverb）+ 材质相关遮挡 + 随空间变化 + **延迟 ≤ 1 tick**
- **纯客户端**；只作用于**我们自己的音源**；原版唱片与其它声音**完全不受影响**
- 任何失败**自动回退**到现在这套 DSP（出声永远优先于效果）

## 三层架构

### 1) 采集层（主线程，每 tick）
- **遮挡射线（沿连线）**：从耳朵到唱片机分段取样（每 ~0.5 格，最多 64 段），
  每命中一个方块就查**材质表**，累加 `occlusionAcc` 与平均 `reflectivity`
- **混响射线（向外）**：从唱片机均匀发射 32~64 条，每条最多 4 次反弹；
  记录命中距离、面法线、材质反射率 → 累加成 **4 个延迟带** + **逐层反射率**
- 射线预算上限（可配）：默认 ≤ 256 条/秒
- 全部在主线程做（world 只在主线程安全）→ 用 `IdentityHashMap` 缓存 BlockState 参数

### 2) 参数层（每 tick）
- 由采集结果算出（与 SPR 同一组量）：
  `directCutoff`（0..1）、`directGain = directCutoff^0.1`、
  `sendGain[0..3]`、`sendCutoff[0..3]`
- **按 tick 做时间常数平滑（约 0.15 s）** —— 这一步就是解决"延迟高"的关键：
  参数不再等音频块，主线程算完立刻写进声源

### 3) 应用层（每 tick，主线程）
- 用 `EXTEfx`（LWJGL 自带，Minecraft 已依赖）给**已捕获的我们的 source**：
  - `alSourcei(src, AL_DIRECT_FILTER, lowpass)` + `AL_LOWPASS_GAINHF = directCutoff`
  - 4 个 aux effect slot（EAXReverb）；`alSource3i(src, AL_AUXILIARY_SEND_FILTER, slot[i], i, filter[i])`
  - slot 参数只在变化超过阈值时更新（避免每 tick 重算）
- EFX 初始化失败 / `alcIsExtensionPresent(ALC_EXT_EFX)` 为假 → **回退 DSP**，并打一条日志

## 材质表（自己推导，MIT，不抄它的配置）

每个方块给一个三元组 `(occlusion, reflectivity, absorption)`：
- **方块声音组**（`state.getSoundGroup()`）：石/木/羊毛/玻璃/金属… → 基础吸声
- **是否完整方块**（`state.isOpaqueFullCube`）：不完整方块按 `non_full_block_occlusion_factor` 打折
- **硬度 / 是否为液体 / 是否金属** 做微调
- 结果缓存进 `IdentityHashMap<BlockState, 参数>`

## 其它细节
- **水下**：`player.isSubmergedInWater()` → 直通再乘 0.1
- **空气吸收**：按距离对 `directCutoff` 再衰减（高频先没）
- **开阔度修正**：无阻挡射线比例 → `cutoff = max(sqrt(openness) * 0.2, cutoff)`（这条继续用，方向对）

## 性能硬指标
- 主线程：每 tick ≤ 2 ms（用 `performance_logging` 打耗时）
- 音频线程：**不参与**（EFX 由引擎/驱动处理）→ 从根上消除块级延迟

### 实现与计划的差异（诚实记录）

1. **遮挡不做"每 0.5 格取样"**，改成 **DDA 体素遍历**（`RayWalk`）。原因：取样法既要靠 epsilon
   续射，又会把同一个方块算两遍；DDA 一次拿到"穿过哪些格子 + 入射面法线"，更准也更快。
2. **`ALC_MAX_AUXILIARY_SENDS` 默认只有 2**（用独立 LWJGL 探针实测），所以写了
   `SoundEngineMixin` 请求 4 个发送 —— 这一步计划里没写，但不做就只有 2 段混响。
   它有安全阀（异常/失败都退回原样调用）。
3. **M4 先做 1 个 slot**（4 个延迟带的能量先合并送 slot 0），M5 才拆成 4 段；与计划一致。
4. **混响段数少的自动降级**：EFX 段数不足时把后段折回前段，不丢能量。

## 安全与开关
- 所有声学代码包 try/catch，**出错绝不影响播放**
- 配置：`physicsSound`（总开关）、`physicsSoundLevel`（强度 = 闷度+余响一起缩放）、
  `physicsAbsorption`（隔墙闷度 k）、`physicsOcclusionPaths`（漏音通路数）、`physicsRays`（精度/性能折中）、
  `physicsStrictOcclusion`、`physicsSoundDirection`、`physicsSoundDebug`（开=材质探针 + 材质表自检 + 每秒一行数值）
- **取证优先**：`physicsSoundDebug=true` 时日志里会出现
  `材质探针: <方块> → 遮挡/反射率/吸声（来源=…）`（每轮最多 6 条、最多 1 秒一次），
  以及开局一次的 `材质表自检`。**"来源=默认值"就是材质表退化的铁证。**
- 每完成一个里程碑就构建 + 装机 + 打日志，确保"随时可回退"

## 调参记录（0.12.6 —— 改了哪些常数、为什么）

> 触发：用户实测 0.12.5「有效果 ✓，但没那么激进，有些场景听不出来 ✗」，
> 追加要求「**隔墙变闷必须明显到一耳能听出来**，优先级高于混响」。
> 本轮**只调参 + 加诊断**：没有新增/删除 mixin，没有动 EFX 架构与调用链。

### 先定位"为什么不够明显"（三个原因，都能指到代码）

1. **开阔度修正在最后一步把遮挡顶了回去**（0.12.5 `Acoustics.evaluate` 里的
   `cutoffWithShared = max(sqrt(avgShared)*0.2, cutoffNoAir)`，没有门槛）：
   站在开阔房间隔一层石头墙 → `avgShared≈0.9` → 下限 `0.19` 直接把
   `exp(-1.0*3)=0.0498` 顶成 **0.1897**。用户听到的"0.2~0.3"就是这个数。
   **而且这个下限与墙厚无关**：一层石头、两层石头、深板岩，下发值全是 0.1897。
2. **8 条偏移射线取最小值**：一条缝 → `occ=0` → `cutoff=1.0` → 滤波器等于没挂
   —— 这就是"有些场景完全听不出来"。
3. `gain = cutoff^0.1`：`0.0498^0.1 = 0.741`，隔墙总音量只掉 2.5 dB，
   感知到的"闷"几乎全来自高频那一段（用户要求"总增益也跟着降一点"）。

### 参数对照表（旧 → 新，及"哪一段听感"）

| 常数 | 旧 | 新 | 管哪一段听感 |
|---|---|---|---|
| `ABSORPTION_DEFAULT`（k） | 3.0（写死） | **4.5**（配置 `physicsAbsorption` 2~9） | 隔墙**闷度**：一层石头墙 0.19 → **0.011**（-14 → -39 dB 高频） |
| 开阔度门槛 `OPENNESS_GATE_OCC` | 无 | **0.6**（遮挡 ≥0.6 时修正失效） | 防止"闷度被开阔空间顶回去"；也修掉"厚墙薄墙一个样" |
| 截止下限 `MIN_DIRECT_CUTOFF` | 0.02 | **0.005** | 完全被挡时能压到多低（验收要求 ≤0.05） |
| 增益指数 `DIRECT_GAIN_EXP` | 0.1 | **0.2** | 隔墙**总音量**：一层石头墙 0.847 → 0.407 |
| 偏移射线规则 | 8 条取最小值 | **数通路** `放宽 = 0.85×min(1,通路/3)` | "一条缝就透"→"要有足够通路才透" |
| `DEFAULT_OPEN_PATHS` | 1（等价） | **3**（配置 `physicsOcclusionPaths`） | 门缝/拐角还透一点，但隔一层墙一定闷 |
| 木板遮挡 | 0.82 | **0.55** | 三档材质对比：玻璃 0.41 / 木板 0.084 / 石头 0.011 |
| 石头反射率 | 0.52 | 0.60 | 混响亮度（次要） |
| 兜底反射率 | 0.40 | 0.60 | 未识别材质/射线未命中的混响基准 |
| `SEND_BOOST` | ×1.0 | **×1.6** | 余响湿度（次要） |
| 衰减时间系数/下限/上限 | 0.25/0.25/4.0 | **0.40/0.45/6.0** | 尾巴长度 |
| EAXReverb `gain` | 0.24 | **0.32** | 混响整体电平 |
| `physicsSoundLevel` 语义 | 只乘发送增益 | **同时乘 k 与发送**；0=等同关闭 | 用户"一个旋钮整体变强/变弱" |

### 建议的默认档位（就是出厂值，不用手动调）

`physicsSound=true`、`physicsSoundLevel=**1.0**`、`physicsAbsorption=**4.5**`、
`physicsOcclusionPaths=**3**`、`physicsRays=32`、`physicsStrictOcclusion=false`、
`physicsSoundDirection=true`、`physicsSoundDebug=false`。

按公式推：**无阻挡 1.0 → 玻璃 0.41 → 木板 0.084 → 石头 0.011**（高频），
石头墙后总增益 0.407。**听感必须由用户实测确认**（见 `tools/AcousticsMath.java` 实跑输出）。

### 一处有意的副作用（诚实记录）

按上面的默认值，`max(0.2*sqrt(shared)*(1-occ/0.6), exp(-occ*4.5))` 里的**开阔度那一项永远赢不了**
—— 也就是计划里那条"开阔度修正"（同一片开阔空间声音能绕过来 → 直通不该被压死）
**对直通截止实际上停用了**。这是有意的：它正是把"隔一层石头墙 0.05"顶回 0.19 的元凶。
- 代码形状保留：把 `physicsAbsorption` 调回 2~3，它就会重新起作用（用户可自测）。
- `SharedAirspace` 仍在混响侧生效（4 个延迟带权重 `w0..w3`、DSP 兜底的 `openness`），
  "开阔空间尾巴长、小房间短促"这条听感不受影响。
- 详见 [CHANGELOG-内部.md](CHANGELOG-内部.md) 的 0.12.6 一节。

### "从最弱到最强"的旋钮顺序（用户自己微调用）

| 想改什么 | 动哪个 | 方向 | 副作用 |
|---|---|---|---|
| 整体变强/变弱（推荐先用这个） | `强度` (`physicsSoundLevel`) | 0（关）→ 2 最激进 | 同时放大闷度与余响；2.0 可能"闷到听不清内容" |
| 只把"隔墙闷"调狠 | `隔墙闷度 k` (`physicsAbsorption`) | 2.0（几乎不闷）→ 9.0（到下限） | 太大时所有材质都会撞到截止下限 0.005，材质差异被吃掉 |
| 门缝/拐角透不透 | `漏音通路数` (`physicsOcclusionPaths`) | 1（最慈悲，接近 0.12.5）→ 9（最严） | 调大后站在门口也可能发闷 |
| 想彻底当墙 | `严格遮挡` (`physicsStrictOcclusion`) | 开 | 连门缝都不透，最容易"听不出来有变化"的反面 |
| 余响多少 | `强度` + `发送基准 SEND_BOOST` | 1.0 → 1.6（默认）→ 更大 | 太大时会"糊" |
| 材质对比度 | `BlockAcoustics.baseFor` 各档遮挡 | 拉开差值 | 需要重新构建 |

## 教训（本项目已经踩过的）
1. 带"上次时间戳"的限频代码，初值**必须** `Long.MIN_VALUE / 2` 或 `0`，否则减法溢出 → 永远 return
2. 平滑系数必须**按时间**算，不能按"调用次数"（音频块大小会变）
3. 改配置/JSON 文件**禁止**用 `-replace` 拼字符串（曾把 mixin 配置写空）
4. 效果类问题先开**调试日志/调试渲染**观测，再动手
