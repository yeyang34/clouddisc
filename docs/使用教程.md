# 歪歪网易云唱片 CloudDisc · 使用教程（v0.3.1）

> **歪歪网易云唱片mod——忠于原版，高于原版**
>
> 游戏内也有同一份教程：按 `K` 或输 `/clouddisc` 打开配置界面，切到「第 3 / 4 节 · 使用教程」。
> 这份文件是给"在电脑上看"的场景准备的，内容一致。
> 遇到任何一步不对，**别反复试**，直接跳到 §9 的表按日志定位，然后把日志发我（§10）。

## 0. 先读这三句

1. **这是测试版，不是发布版。** 代码能编译、能出包，但**还没有人在游戏里跑过**（我这边没有可运行的游戏环境）。所以第一次启动失败是完全可能的，而这正是我们要一起验的东西。
2. **本次只测两件事**：① 唱片机真的播我的音乐、且原版唱片声不出声；② 同局域网两台机进度一致。
3. **本版同步只支持局域网**（或同一台电脑开两个客户端）。跨公网要等 v0.2 的信令，原因见 §6 开头。

## 2. 第一步：启动游戏，确认 Mod 被加载

启动一次游戏（进到主界面就行，不必进世界），然后做两件事：

**① 看 ModMenu**（你已经装了 `modmenu-7.2.2`）：模组列表里应该出现 **CloudDisc 云唱片**。

**② 看日志里的诊断块**。打开 `logs\latest.log`（用记事本，Ctrl+F 搜 `CloudDisc`），你应该看到这样一段：

```
[CloudDisc] ===== 诊断信息（遇到问题请把这一段连同后续报错一起发给我）=====
[CloudDisc] 游戏目录 : ...\versions\1.20.1-Fabric 0.19.3
[CloudDisc] 音乐目录 : ...\versions\1.20.1-Fabric 0.19.3\clouddisc-music   ← 把 .ogg / .wav 放在这里
[CloudDisc] 缓存目录 : ...
[CloudDisc] 配置文件 : ...\config\clouddisc.json
[CloudDisc] 默认音源 : local   改名前缀: "@"
[CloudDisc] UDP 端口 : 25566   局域网发现: true   聊天兜底: true
[CloudDisc] 播放用法 : 用铁砧把唱片改名为 "@<音源>:<曲目>"，例如 "@local:test-metronome"，再放进唱片机
[CloudDisc] ==========================================================
```

**这一步的价值**：`音乐目录` 那一行是游戏的**真实**判定结果。以后不管什么找不到文件的问题，都以这一行为准。

**如果 ModMenu 里没有 CloudDisc** → jar 放错目录了（放到了 `.minecraft\mods` 而不是版本目录），把它移到 §1 表格里的路径。

## 3. 第二步：确认测试音频在位

`clouddisc-music\test-metronome.wav` 应该已经在（约 5 MB，60 秒）。

这个音频是**专门为"听同步"做的**，不是随便找的歌：

| 特征 | 用途 |
|---|---|
| 每秒一声短促的"哒"（880 Hz，30 ms 衰减） | 两个人**同步**时你听到的是一声干净的脆响 |
| **不同步**时 | 会听到"哒哒"双击、或者像加了延迟的效果（俗称 flamming）——差几十毫秒就明显能听出来 |
| 每 10 秒换成更高的音（1760 Hz） | 确认两个人处在**同一个循环位置**（而不是差了好几秒） |
| 总长 60 秒 | 够你听同步，也够你等到它自然结束 |

> 想自己先听听这个文件对不对：直接用系统播放器打开它。你会听到规律的节拍器。

## 4. 第三步：用铁砧给唱片改名

**最快的方式**（创造模式）：

```
/give @s minecraft:jukebox
/give @s minecraft:anvil
/give @s minecraft:music_disc_cat
```
把它俩放在地上，然后：

1. 右键**铁砧**打开界面
2. 把 `music_disc_cat` 放进**第一个格子**
3. 在**上面的名字输入框**里，原样输入：

```
@local:test-metronome
```

4. 从**输出格**取出改名后的唱片（会消耗经验等级，创造模式无所谓）

**规则说明**：

- 开头的 `@` 是"这是 CloudDisc 唱片"的标记（可在配置里改）。**没有这个前缀的唱片，本 Mod 完全不碰**——所以普通改名唱片不受影响。
- `local` 是音源 provider：本地文件。
- `test-metronome` 是曲目 key，对应 `clouddisc-music\test-metronome.wav`（**不用写扩展名**，会自动找 `.ogg`/`.wav`/`.mp3`/`.flac`）。
- 任何**原版音乐唱片**都可以这样改名（cat / blocks / mellohi / pigstep… 都行）。
- 名字上限约 50 字符（原版铁砧限制），所以 key 要短。

**顺手提醒一个坑**：原版唱片放完后，服务端会在"这张唱片自己的时长"到点后停止播放（cat 约 185 秒、blocks 约 345 秒）。我们的音乐也受这个上限约束，所以**测长曲子请用长唱片**（`music_disc_blocks` 最久）。

## 5. 第四步：放进唱片机，看会发生什么

把改名后的唱片**右键塞进唱片机**。预期：

| 应该发生 | 说明 |
|---|---|
| 约 **2 秒后**开始规律打拍子 | 那 2 秒是"统一开始刻"的预缓冲 lead，多人同步必需，正常现象 |
| **完全听不到** cat 原本的音乐 | 这就是"真替换"的判据：不是被盖住，是根本没出声 |
| 把"唱片机/音符盒"音量滑块拉到 0 → 静音；拉回来 → 恢复 | 证明走的是 MC 自己的音量体系 |
| 走远 → 声音随距离衰减 | 证明是定位在唱片机坐标的空间音源 |
| 右键取出唱片 → 声音立刻停 | 走原版停止逻辑 |

**v0.1 已知的两个"不像原版"的地方**（我刻意留着，原因在设计文档 §2.4）：

- **鹦鹉不会跳舞**（原版唱片机会让附近鹦鹉跳舞）
- **HUD 不显示"正在播放：xxx"**

这两个是我当前 Mixin 挂点的取舍，v0.2 改成 `WorldRenderer#playSong` 挂点后就会恢复。**它们不影响音频本身**。

## 6. 第五步：局域网双人同步测试

### 为什么本版只能局域网

要有"玩家之间"的通道，而**原版服务器不会转发任何自定义数据**（我用反编译源码确认过：服务端那个处理函数是空方法）。原版唯一免费的广播通道是聊天，但 1.20.1 的聊天有签名与限流两道坎（同窗口第 11 条消息直接踢人），而"聊天通道的接收端"我**刻意没接**（必须实机验证，见教程 §11）。

所以本版可用的通道是 **UDP 点对点**：同一局域网内靠广播自动发现彼此。**跨公网需要先交换公网地址（v0.2）**，本版做不到。

### 准备

- 两台机器**接同一个路由器/同一个 WiFi**，都装好这个 mod 和那份测试音频
- 进**同一个世界**（一个开局域网房间/服务器，另一个连进去）
- 站到同一台唱片机旁边

### 怎么看有没有发现同伴

看日志里这一行（右键放碟时会打）：

```
[CloudDisc] 收到世界事件 1010（唱片机开始播放）@ ... ｜本机待确认插入=... 已有会话=... 可见同伴=true
```

- `可见同伴=true` → 局域网发现成功
- `可见同伴=false` → 两个客户端互相没看见（防火墙/广播被挡/不在同一网段）。**同一台电脑开两个客户端**时也必须注意：要给两个客户端配**不同的 UDP 端口**（见 §8 的 `udpPort`），否则第二个客户端绑不上端口。

### 怎么判断同步成功

放碟后听：

| 你听到 | 结论 |
|---|---|
| 每秒**一声干净脆响** | ✅ 同步（偏差大概在几十毫秒内） |
| 每秒"**哒哒**"双击 / 有金属味的抖动 | ❌ 没同步：两个客户端差了几十~几百毫秒 |
| 两边的"高音小节点"不在同一秒 | ❌ 差了整整几秒（某个客户端起播严重滞后） |
| 一开始同步，**几分钟后**开始出现双击 | ❌ 有漂移（这才是我最想知道的） |

**建议的测试顺序**（每一步都记一下结果，方便定位）：

1. 单人：确认 §5 表格全部符合 → 说明"替换原版声音"这条链路通了
2. 双人：放碟，听是不是一声脆响
3. 双人：**中途加入**——一个人先在唱片机旁，另一个人过 30 秒再走过来/再进服，听新来的人是不是**从正确的位置**接上（不是从头开始）
4. 双人：**取出唱片再放一次**，看会不会有一次响两次/旧声音不停
5. 双人：放 2~3 分钟，看有没有逐渐错开

## 7. 换成你自己的音乐

### 支持格式

| 格式 | 说明 |
|---|---|
| **OGG Vorbis** | 体积小、可精确跳转定位；Minecraft 自带解码器，零额外依赖 |
| **WAV（16-bit PCM）** | 谁都能导出，适合快速试；体积大（60 秒立体声约 10 MB） |
| **MP3** | 已支持（内置 JLayer 解码，LGPL-2.1，见 `THIRD-PARTY.md`）。**在线音源基本都返回 mp3**，所以这条是网易云能用的前提 |

FLAC 暂不支持（需要再引入一个 LGPL 解码库）。

### 转换方法

有 ffmpeg 的话：

```bash
# MP3/FLAC → OGG（推荐）
ffmpeg -i "我的歌.mp3" -c:a libvorbis -q:a 5 "我的歌.ogg"

# 普通 WAV → 16-bit PCM WAV（如果它本来就是 16bit，直接改名也行）
ffmpeg -i in.wav -c:a pcm_s16le -ac 2 out.wav

# 顺手把采样率降下来可以显著减小解码压力（可选）
ffmpeg -i in.mp3 -ar 44100 -ac 2 -c:a libvorbis -q:a 5 out.ogg
```

没有 ffmpeg：用 **Audacity**（免费）打开音频 → `文件 → 导出 → 导出为 OGG`，或导出 WAV 时选 `16-bit PCM`。

> ⚠️ 别用不知名的"在线音频转换"网站：那等于把你自己的音频文件上传给别人。本地用 ffmpeg/Audacity。

### 文件放哪、名字怎么对上

放进 `clouddisc-music\`（以日志里的"音乐目录"为准），然后：

| 文件名 | 铁砧里写 |
|---|---|
| `clouddisc-music\我的歌.ogg` | `@local:我的歌` |
| `clouddisc-music\sub\song.ogg` | `@local:sub/song`（支持子目录） |
| `clouddisc-music\test.wav` | `@local:test` 或 `@local:test.wav` |

中文/空格文件名都能用（解码走的是 Java 读文件，不依赖本地编码）。**不要**用 `..` 往上跳目录。

## 7.5 用网易云分享链接（实测可用范围）

这一版**只需要写 `@` + 网易云歌曲 id**，而且**后面可以跟备注**（歌名、歌手、备注都行，会被忽略）：

| 铁砧里输入 | 字符数 | 说明 |
|---|---|---|
| `@186016` | 7 | **最简写法** |
| `@186016（晴天）` | 13 | 备注可选；播放时显示联网查回的真名，备注拼在真名后面 |
| `@186016 晴天` / `@186016-晴天` | | 备注用别的分隔符也行（只认**开头**那串数字） |
| `@https://music.163.com/song?id=186016` | 37 | 直接粘分享链接，也会自动识别 |
| `@local:test-metronome` | | 想放本地文件时用 `local:` 显式指定 |

铁砧输入框上限约 50 字符，所以备注最多能写 ~35 字（`@` + 最多 12 位 id + 备注）。

**怎么拿歌曲 id**：网易云里点「分享 → 复制链接」，你会得到类似

```
分享XX的单曲《晴天》: https://music.163.com/song?id=186016 (来自@网易云音乐)
```

`id=` 后面那串数字就是；或者直接把链接那一段抠出来粘上（**别把"分享XX的单曲…"整段粘进去**，超 50 字符）。

### 关键：只放"匿名就能听的内容"

我实测抽样了 8 首歌（2026-10）：

| 曲目类型 | 实测结果 |
|---|---|
| **免费 / 非独家** | ✅ `200 + audio/mpeg`，302 到 CDN 的 mp3（3–5 MB）→ **能放** |
| **VIP / 独家 / 下架 / 地区受限** | ❌ 302 到 `https://music.163.com/404`，返回 107 KB 网页 → **放不了** |

放不了时**日志会明确告诉你**：`拿到的是 text/html;charset=utf8（107191 字节的网页/JSON），不是音频文件…`
看到这句就是"这首歌匿名不可播"，**不是 bug**。

### 想放 VIP 曲目：必须靠你自己的服务

只有一条路——你自己有一个能解析播放地址的服务（你自己的账号、你自己的接口），填进配置：

```json
{
  "neteaseEnabled": true,
  "neteaseEndpoint": "http://127.0.0.1:3000/song/url?id={id}"
}
```

- `{id}` 会被替换成歌曲 id；
- 你的服务返回 JSON `{"title":"歌曲名","url":"http://.../x.mp3"}` 即可（也可直接返回音频流）；
- **本 Mod 不内置任何接口地址、不内置任何人的账号或 cookie、不解密受保护格式。** 这一条完全由你自己提供。
- 本地服务（`127.0.0.1`）由**你自己** provider 解析出来的地址是允许的（不会被安全策略拦），放心用。

### 不支持的输入

| 输入 | 为什么不行 |
|---|---|
| `163cn.tv/xxxx` 短链 | 实测它只跳网页，解析不出音频。请用完整页面链接或直接填 id |
| 整段分享文本 | 超铁砧 50 字符上限，只抠链接那一段 |
| QQ音乐/酷狗/其他平台链接 | 不认识（只有 `local` / `163` / `url` 三个音源） |

### 自己先验证某首歌能不能放

浏览器里打开（把 `<id>` 换成歌曲 id）：

```
https://music.163.com/song/media/outer/url?id=<id>.mp3
```

- 直接开始播放/下载 mp3 → 游戏里能放
- 跳到网易云的 **404 页面** → 游戏里放不了（VIP 等）

## 8. 配置文件详解

`config\clouddisc.json`（首次启动自动生成，改完重启生效）。常用的就这几个：

| 项 | 默认 | 什么时候改 |
|---|---|---|
| `discNamePrefix` | `"@"` | 想用别的前缀（例如 `"♪"`）。注意：**所有以它开头的唱片都会被接管** |
| `defaultProvider` | `"local"` | 想默认走自建服务时改 |
| `localMusicDir` | `"clouddisc-music"` | 想把音乐放别处（相对路径相对游戏目录，也可写绝对路径） |
| `udpPort` | `25566` | **同一台电脑开两个客户端时必须改成不同值**（例如 25566 / 25567） |
| `enableLanDiscovery` | `true` | 关掉后不再广播发现（就不会自动找到同伴了） |
| `enableChatRelay` | `true` | 聊天兜底通道。**有副作用**（原版玩家会看到乱码行），不想用就设 `false` |
| `startLeadTicks` | `40` | 统一开始刻的提前量（40 刻 = 2 秒）。**网络慢/文件大就调大**（例如 100 = 5 秒） |
| `prebufferMs` | `1500` | 预缓冲时长。经常卡顿就调大（例如 3000） |
| `maxDriftMs` | `150` | 超过这个偏差就 seek 纠偏。想更严格可以调到 80 |
| `jukeboxVolume` | `4.0` | 与原版唱片一致，一般不用动 |
| `cacheMaxMb` / `maxTrackMb` | `512` / `64` | 缓存与单曲体积上限 |
| `neteaseEnabled` / `neteaseEndpoint` | `false` / `""` | **默认关闭**。只填你自己有权使用的接口地址，`{id}` 会替换成唱片里的 key。本 Mod 不内置任何接口与凭据，也不支持解密受保护格式 |

## 9. 出问题了怎么查（照着日志对）

日志：`...\versions\1.20.1-Fabric 0.19.3\logs\latest.log`，搜 `CloudDisc`。按时间顺序，正常应该依次出现这一串：

```
[CloudDisc] 检测到 CloudDisc 唱片: @local:test-metronome -> local:test-metronome
[CloudDisc] 收到世界事件 1010（唱片机开始播放）@ ... ｜本机待确认插入=true 已有会话=false 可见同伴=...
[CloudDisc] 开始解析曲目: provider=local trackId=test-metronome
[CloudDisc] 解析成功: test-metronome → ...\test-metronome.wav｜预定 40 刻后开始
[CloudDisc] 准备音频: uri=...｜曲内起始位置=0ms｜预缓冲目标=1500ms
[CloudDisc] 已就绪: test-metronome.wav（44100 Hz / 1 声道 / 时长 60000ms）
[CloudDisc] SoundLoader.getStream 被调用: 原始 id=clouddisc:sounds/stream/1.ogg → 归一化=clouddisc:stream/1 → 命中我们的流
[CloudDisc] 已开始播放: test-metronome.wav（从 0ms 起）｜流 id=clouddisc:stream/1｜预缓冲 1500ms
```

**对不上就查这张表**：

| 日志停在哪 | 说明什么 | 怎么办 |
|---|---|---|
| 完全没有 `检测到 CloudDisc 唱片` | 右键那一下没被识别 | ① 名字是不是真以 `@` 开头？② `@` 后面有没有多余空格？③ 你拿的确实是**音乐唱片**类物品吗？④ 是不是对着唱片机右键的？ |
| 有"检测到"，但**没有** `收到世界事件 1010` | 唱片没真的进机器（被别的方块拦了/右键的是别的面） | 换个角度对着唱片机正面再放一次 |
| 有 1010，但 `本机待确认插入=false` 且 `已有会话=false` | 这张唱片不是"你亲手放进去的" | 本版不支持漏斗自动塞入（会回落原版声音）。请手动放 |
| 有 `解析失败 ... ` | 找不到文件 / 文件格式不支持 | 看报错里的完整句子。常见：文件名不匹配、是 MP3（本版不支持）、WAV 不是 16-bit PCM |
| 有"解析成功"但**没有** `SoundLoader.getStream 被调用` | 声音系统没走到取流那一步 | 最常见原因：**你把"唱片机/音符盒"音量调成 0 了**（源码里音量为 0 会在取流前直接返回）。先把音量拉起来再放一次 |
| 有 `getStream 被调用` 但写着**未注册** | id 没匹配上（我最想看到的失败） | **把这个完整行发我**，我要归一化后的 id |
| 全都有了、也"命中我们的流"，但**没声音** | 卡在 OpenAL 进数据这一环 | ① 检查系统默认音频设备；② 把 `prebufferMs` 调到 3000 再试；③ 发我日志 |
| 有声音，但夹杂爆音/断续 | 欠载（解码跟不上或磁盘/CPU 繁忙） | 把 `prebufferMs` 调大（3000~5000），`startLeadTicks` 调到 60~100 |
| **游戏启动就崩** | Mixin 没注入成功之类的加载期问题 | 把 `crash-reports\` 里最新的那个文件整个发我 |
| 两个人不同步 | 见 §6 的判断表 | 先确认 `可见同伴=true`，再看两人日志里的"已开始播放"时间差 |

---

## 10. 出问题就把这些发我

1. **`logs\latest.log` 整个文件**（或至少把 `CloudDisc` 相关的所有行 + 报错堆栈）
2. 如果有崩溃：`crash-reports\` 里最新的那个文件
3. 一句话描述：**你做到哪一步、期望什么、实际看到什么**（例如"放碟后日志到'解析成功'就没了，没有声音"）
4. 你的配置：`config\clouddisc.json` 内容

有这四样，绝大多数问题我能直接定位到具体哪一环，不用你反复试。

## 11. v0.1 已知限制（别当成 bug）

| 限制 | 说明 |
|---|---|
| **网易云只支持"匿名可播"的曲目** | VIP/独家/下架曲目会返回 404 网页；要放只能靠你自己的 `neteaseEndpoint`（见 §7.5） |
| **跨公网不能同步** | 只能局域网；UDP 打洞 + 信令是 v0.2 |
| **聊天通道收不到消息** | 出站已实现（含限流），**入站 hook 刻意留空**——那部分必须实机验证才能确定接法 |
| 鹦鹉不跳舞、HUD 不显示曲名 | 挂点取舍，v0.2 改成 `WorldRenderer#playSong` 后恢复 |
| 漏斗自动塞唱片不支持 | 回落原版声音；v0.3 用"读方块实体"补 |
| FLAC 不支持 | 需要再引入一个 LGPL 解码库（v0.3） |
| 播放时长上限 = 所选原版唱片的时长 | 长曲用 `music_disc_blocks`（约 345 秒） |
| 起播有约 2 秒延迟 | 统一开始刻的预缓冲，多人同步必需 |

## 12. 一句话总结你要做的

> 装好了 → 进游戏 → 铁砧把 `music_disc_cat` 改成 `@local:test-metronome` → 放进唱片机 → 2 秒后听节拍器。
