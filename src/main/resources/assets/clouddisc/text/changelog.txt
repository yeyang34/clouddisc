0.12.42 — 汇总 0.13.0 — 物理声效第二代：房间 + 传送门模型

【一句话】

判断"闷不闷"的依据，从「直线上有没有方块」改成了「声音有没有路可以走过来」——
这是 Valve（Portal 2 / Half-Life: Alyx与 Steam Audio 的做法。

【物理声效】

- 房间连通模型：从唱片机和你各做一次空气洪泛，两片空气相通（门/走廊/窗）→ 按绕行距离轻微衰减；
  不相通（真墙、关着的门、屋顶）→ 由材质遮挡决定，明显闷
- 因此：房间里的柱子、家具、台阶、半砖再也不会让声音变闷（这是过去几版最反直觉的问题）
- 开门 = 像挖了个洞一样漏音；关门 = 明显闷（无碰撞体积的方块，如开着的门/活板门、
  火把、花、草，一律按空气处理）
- 通透判据与材质表对齐：树叶 0.12（通透）｜玻璃 0.52｜木板 0.55｜石头 1.00（明显挡声）
  于是"一层木板屋顶完全透明"这类问题消失
- 站姿影响修正：站在唱片机正上方时，屋顶也会被正确计入（过去偏移射线起点会被抬到屋顶之上）
- 过渡丝滑：遮挡变化做了时间平滑 —— 变闷约 1.1 秒（像门真的合上）、
  变清楚约 1.0 秒；混响发送量另有约 0.5 秒的平滑，不会突然消失或突然出现
- 大空间余响更饱满（混响发送 +30%），小房间不受影响

【配置界面】

- 顶部胶囊标签栏、每行卡片 + 左侧色条、控件列对齐、底部按钮与输入框同列
- 自适应布局：笔记本小窗口不再重叠（控件宽度/行距/高度都按窗口算）

0.12.13 —— 门终于按"有没有真的挡住"来判断 + 物理声效方案回滚

- **回滚**：物理声效回退到 **0.12.6** 那套（0.12.7 / 0.12.8 / 0.12.9 的改动全部撤回 ——
  那几版虽然在修门，但把"混响被掐死""能量预算砍直通""一层/两层石头分不出"等问题带了进来，实测体验更差）。
- **重做门遮挡（本次核心）**：以前只判断"这一格有没有碰撞体积"，
  于是**开着的门**（薄板贴在侧面）也被算成"挡" —— 表现就是你实测的"开关门一样闷、只有挖掉才清晰"。
  现在改成**射线与碰撞形状真正求交**：
  - 关着的门（薄板横在门口）→ 撞上 → **明显闷**
  - 开着的门（薄板贴在侧面）→ 从旁边过 → **清晰**
  - 半砖/玻璃板/楼梯/栅栏 → 只有射线真的穿过实体部分才算（不再是"一刀切打折"）
  - 满格方块（石头/木板/原木）→ 直接判挡（同时避开浮点边界误差）
- **漏音规则收敛**：需要 **≥6/8** 条偏移通路才放宽，且最多削弱 40%（旧版 3/8 就削弱 85%，门边墙角会把遮挡抹平）。
- 实测：关门 `遮挡=0.44 → 截止 0.138`（−17.2 dB，明显闷）；开门/挖掉 `0.00 → 1.000`（清晰）；
  玻璃 0.20（轻微闷）、石头 1.00（最闷）—— 三档仍分得开

0.12.9 —— 修「进游戏没音效、整体又闷又小声」（混响被掐死 + 预算砍直通）

- **现场日志里能直接看到两个数不对**：`sendCutoff=[0.001,0.001,0.001,0.001]`（4 路混响自己的低通
  被压到 0.001 ≈ 静音）；`直通增益=0.153` 之后又被能量预算乘了 0.68 倍（真正下发的是 0.104）
- **Bug A：混响 4 路发送的高频被算成 0.001（等于把混响掐掉）**
  · 根因：混响发送的低通用的竟是"直通那条链路"的公式 exp(-遮挡×4.5)，遮挡 2.1 时它 ≈ 8e-5
  · 改法：混响高频只跟"混响路径自己吸掉多少高频"走（逐层反射率），遮挡只留温和系数 0.5，
    并且**加硬下限 0.20**
  · 结果（用你日志的真实输入复算）：0.001 → 0.371~0.382；通畅时 1.000 → 0.840（基本不变）
    ⇒ 混响那 4 路终于能出声了
- **Bug B：能量预算又把直通砍了一刀**
  · 根因：预算把"一点声音都没送出去"的 4 路发送也当成满能量，于是预算 0.68，直通被再乘 0.68 → 又闷又小声
  · 改法：预算按**有效湿声能量**算（发送增益 × 发送高频 × 混响增益）；直通最多降到一半
  · 结果：你日志第 1 行 预算 0.683 → 1.000（不再削直通）；通畅那一行 0.428 → 0.736
    （原来在开阔地也白掉 -7.4 dB）
- **顺带：直通加"听得见"的下限**（你说的"要明显，不是消失"）
  · 直通增益 ≥ 0.25、高频 ≥ 0.02：两层石头墙那行 0.153 → 0.250、0.006 → 0.020
  · 代价（诚实说）：一层石头墙的高频也被抬到 0.02，所以"一层/两层石头"的高频不再有区别
    （总增益仍有 0.407/0.250 的区别）；极厚墙的总增益也从 0.067 抬到 0.25 ——
    觉得太响就把「强度」调小
- **日志新增两个字段（排障用）**：`能量预算(直通倍率)` 与 `有效发送能量`；
  注意 **日志里的"直通增益"是预算之前的值**，乘上"直通倍率"才是真正下发值；
  预算真削了东西时会多打一行 `物理声效·能量预算: …`
- **离线自检**（不用启动游戏）：新增 tools/PhysicsParamsTest.java，直接调用生产代码的三个纯函数，
  用你日志里的真实输入复算并断言（完整输出见 docs/0.12.9-复算与自检输出.txt）
- **没动 EFX 架构**：aux slot / EAXReverb / 滤波器拓扑一点没变
- 请实测（都看 `物理声效[M7]` 那行）：
  · 隔一层/两层石头墙：应"明显发闷但**听得见内容**"，且余响（混响）**能听见**
  · 站到唱片机旁边拆掉墙：应立刻变亮变清楚
  · 想更明显：加大「强度」；想更闷：加大「隔墙闷度 k」
- 老规矩：只作用于我们自己的声源；原版唱片与其它声音不受影响；出错自动回退，出声优先

- **新增离线自检** tools/OcclusionWalkTest.java（真实 VoxelShape 几何 + 假世界跑生产同一条累加路径）：

0.12.6 —— 物理声效调参：隔墙"变闷"明显加强 + 材质探针

  一层石头墙后面**实际下发**的高频截止 0.19 → **0.011**（约 -14 dB → -39 dB，高频几乎全砍），
  一耳朵能听出来（以前"一层墙"和"两层墙"下发的是同一个数，加厚完全听不出）
- **修掉两个"不够明显"的真原因**：
  · 以前算完遮挡后又被"开阔空间"修正顶回去（下限 ≈0.19）→ 现在遮挡达到 0.6 时该修正一律失效；
  · 以前 8 条偏移射线"取最小值"，一条缝就把遮挡抹平 → 现在改成**数通路**：
    要 **3 条**以上通透射线才明显放宽，且最多只能把遮挡降到原值的 15%
- **总增益也跟着降**（不只砍高频）：直通增益 截止^0.1 → 截止^0.2，隔一层石头墙总音量也掉到 ≈0.41

- **强度旋钮真正有用**：以前只调"余响"，现在**同时**调"闷度 + 余响"；
  **0 = 等同关闭**、1 = 默认、**2 = 非常激进**
- **混响更明显**：发送基准 ×1.6、默认衰减时间加长、兜底反射率 0.40 → 0.60
- **新增「材质探针」诊断**（打开"调试日志"后生效）：每轮把真正命中的方块打一行，例如

0.12.0 —— 先学会"认出哪条声音是我们自己的"（为下一版铺路）

- **做了什么**：在我们自己那条声音真正开始播放时，从 Minecraft 的音频系统里**精确记下它的编号**
- **为什么必须单独做这一步**：下一版要把"隔墙变闷"交给**音频引擎自带的效果**，
  而引擎上的效果是"挂在某一条声音上"的 —— **编号认错就会去改别人的声音**（绝对不能发生）；
  所以先把"认得准、认不出来就什么都不做"这条底线立起来
- **这一步本身不改听感**：只记编号，外带打一行日志 `物理声效: 捕获到声源 id=N（EFX …）` 方便排障
- 老规矩：只作用于我们自己的声音；原版唱片与其它声音不受影响；出错自动跳过
0.11.3 / 0.11.2 —— 修"拆了墙还闷好几秒"

- **现象**：隔墙 / 拆墙之后，闷或亮要**等好几秒**才变过来；换首歌、换台机器，等的时长还不一样
- **根因（说人话）**：那个"慢慢过渡"是按**音频块的个数**算的，可音频块的大小会变
  （一块约 4096 个样本 ≈ 85 毫秒），再叠加引擎预队列（约 4 秒）→ 手感就是"延迟好大"
- **修法**：过渡改成**按时间**算（固定约 0.15 秒收敛）—— 块大块小都一样
- **诚实的结论**：变化确实快了，但**没有根治** —— 只要效果还在我们自己的音频数据上做，
  就一定要等"下一个音频块"；这条限制要到 0.12.1 起**换成引擎自带效果**才彻底消掉
- 老规矩：只作用于我们自己的声音；出错自动跳过

0.11.1 —— 修"物理声效一直不生效"（一个整数溢出的坑）

- **现象（按根因推断，当时没留档）**：进游戏后效果完全不出现，一直"没反应"
- **根因**：代码用"上次评估的时间"做限频，初值取成了**整数能表示的最小值**；
  第一次相减就**溢出**（结果变成负数）→ 比较永远不成立 → 评估**永远不执行**
- **修法**：初值改成"最小值的一半"（留出相减空间），并把这个坑写进文档，避免再踩
- 老规矩：出错自动跳过，出声优先

────────────────────────────────

0.11.0 —— 物理声效第二版：自己在家做"低通 + 混响"

- **这一版能做的三件事**：
  · **隔墙变闷**：从唱片机到耳朵打射线，看"中间挡没挡"，挡了就把高频压低
  · **余响**：自己写了一个**简易混响**（小房间短、大厅长；铺了羊毛的房间更干）
  · **开阔度**：周围空旷时，声音更"绕得过来"一点
- **做法**：在我们自己的音频数据上处理 —— 一阶低通（截止在约 450 Hz ~ 20000 Hz 之间按遮挡取值）
  + 4 个并联延时（29.7 / 37.1 / 41.1 / 43.7 毫秒）+ 2 个串联全通（5.0 / 1.7 毫秒）
- **已知短板（下一版就是冲它去的）**：
  · **慢**：参数只能跟着音频块走 → 隔墙 / 拆墙要等（这一版被吐槽最多的点）
  · **粗**：只知道"这条线上挡没挡"（当时的记录写作 **16 条射线**）——**没有材质区别**
    （石头和木板一样闷）、**没有反射、没有方向**
  · **结论（诚实版）**：**这条路的上限就在这里** —— 后来从 0.12.1 起换成与 Minecraft 音频引擎同层的做法
- 老规矩：只作用于我们自己的声音；原版唱片与其它声音不受影响

0.10.0 —— 物理声效第一版：射线 → 遮挡 → 低通

- **新增（实验性）**：唱片机的声音开始"看空间"了 —— 从唱片机到耳朵连一条线，
  中间隔着方块就把高频压低一点（**隔墙听上去会闷**）
- **做法**：每隔几刻打一次射线，算出"中间隔了多少" → 一个 0~1 的遮挡度 → 对我们自己的声音做低通
- **当时就知道的限制**：只有"挡 / 不挡"两档（**分不出材质**）；参数变化要等；
  而且遮挡度一变是**一步跳**的（会有轻微"啵"声）—— 后面几版一直在补这些
- 老规矩：只作用于我们自己的声音；出错自动跳过
0.9.9 / 0.9.8 —— 修好"玩一会儿就听不见、对方听到原版"

- **根因**：客户端过去只在"通道未就绪"时才向服务端中继续报，而"就绪"取决于"最近收到过应答"。
  应答一过期就出现一段**一个通道都没有**的窗口（日志实测 `udp=0, relay=0, chat=0`）——
  恰好在这段窗口里放碟 → 同步消息发不出去 → **跟随方**只能听到原版唱片声
  而且续报有 20 次上限（每 3 秒一次）→ **约 7 分钟后就静默失效**，这正是"过了一会"的来源
- **修法**（三处，全在客户端）：
  - 中继应答有效期 60 秒 → **10 分钟**
  - 收到应答就**重置**续报计数（不再撞上限后停摆）
  - **无论是否就绪，每 20 秒续报一次**（原来只在未就绪时补报）
- **服务端不用动**（服务端组件自 0.4.4 起一行未改，协议已冻结）
- 对应的现象：跟随方听到原版、时好时坏、退房重进有时恢复 —— 现在都应消失
0.9.6 / 0.9.5 / 0.9.4 —— 插入瞬间的体验 + 令牌可视化

- **修好**：有时插入唱片会先响一下**原版唱片声**，几秒后才切成网易云
  原因：会话要等"查歌名 + 换地址"完成才登记，而那 1~3 秒里别人来问"谁在放什么"，
  我们这边"看起来什么都没有" → 对方按设计补放了原版声。
  现在改用**右键那一刻就存在的占位标记**回答询问（CLAIM："这块归我，先别放原版"），
  并把"无人认领"的等待窗口从 0.3 秒放宽到 2 秒 —— 那几秒原版声没有了
- **新增**：配置界面第 2 节多了「**解析服务令牌**」一栏
  - 以前令牌只能改 JSON，或塞在地址里（界面看不到）→ 现在**看得见、改得动**
  - 令牌轮换时：服务器改一下 → 大家在界面粘新令牌 → 保存（不用换 jar）
- **整理**：地址与令牌统一成"地址一栏 + 令牌一栏"（地址里不再夹令牌）

0.9.3 —— 单人 / 局域网也能解除唱片时长限制

- **修好**：附加组件 `clouddisc-jukeboxlib` 之前**只在独立服务器上生效** ——
  单人游戏、或你自己开房（局域网）时完全用不上
  原因：它被标成了"只对服务端应用"，而**单人/局域网的服务端是跑在你客户端进程里的** → 现已改为**两端都应用**
- 现在的适用范围：
  - **单人 / 你开房**：自己装上就用（连进来的朋友**哪怕没装 Mod** 也听得到完整一首）
  - **别人的服务器**：需要**服主**装（客户端装没用 —— "放完了吗"的判断在服务端跑）
- **实测通过**：用游戏里**最短的唱片**放一首 4 分多钟的歌 → 完整播完；**拔碟立刻停**；换碟正常
- 附加组件版本：**1.0.1**（旧的 1.0.0 请删掉，两个同时放会冲突）
0.9.2 / 0.9.1 / 0.9.0 —— 长曲与"受唱片时长限制"这件事

- **修好**：歌比原版唱片短时，会准确停在**真实结尾**（以前会提前约 3.5 秒断掉 —— 那是拿"已交给音频引擎的字节数"当进度造成的假象）
- **新增（可选）**：**服务端附加组件** `clouddisc-jukeboxlib`
  - 服主把它放进服务端 `mods/`，**长歌就不再被原版唱片时长掐断**（所有玩家都受益，连没装 Mod 的人也听得到完整的一首）
  - 服务器上其他人用**原版唱片完全不受影响**（只对自定义名以 `@` 开头的唱片生效）
  - 不装它也照常工作 —— 只是长歌会被唱片时长限制
- **回归干净行为**：音乐 Mod 不再去猜"这次停止是自然放完还是玩家拔碟"
  → 原版说停就停（**拔碟即停 换碟正常**），不再出现"停不下来 / 换不了碟"
- **兼容性**：`fabricloader >= 0.15.0` —— 同一个 jar 在客户端（0.16.14）与服务端（0.15.11）都能加载
