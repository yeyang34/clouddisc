0.12.8 —— 修「0.12.7 遮挡恒为 0、声效全无」

- **0.12.7 失效了**：装进游戏后「遮挡完全不生效（遮挡累积永远是 0.000）、声效都没有」。
  根因：0.12.7 把"这一格挡不挡"改成了只依赖引擎的 VoxelShape.raycast 一条路，
  现场它静默返回 null（= 判成"不挡"）→ 整条遮挡链路全灭，只剩混响（所以听感是"有混响但不闷"）
- **改成"两条腿走路"，不再可能静默归零**：
  · 满格体素（石头 / 玻璃 / 原木 / 木板 / 关着的门）→ 直接判挡，不调用求交；
  · 只有不满格/多盒的形状（楼梯、栅栏、半砖、活板门、玻璃板）才逐盒精确求交（保留"缝里能过"的精度）；
  · 再加一道安全网：碰撞形状取不到 + 方块是不透明完整方块 → 仍按挡算
- **日志升级（排障关键）**：物理声效[M7] 那行现在带 `ver=0.12.8` 和
  `主射线走格=N 实心格=M 判定挡=K` —— 一眼分辨"路径上真没实体"（实心格=0）
  还是"有实体但没判定中"（实心格>0、判定挡=0）；启动日志也带版本号
- **新增离线自检** tools/OcclusionWalkTest.java（真实 VoxelShape 几何 + 假世界跑生产同一条累加路径）：
  1 格墙≈1.00 / 2 格墙≈2.00 / 关着的门≈0.44 / 开着的门=0 / 半砖上方擦过=0 /
  旁边空气格=0 / 与薄板平行=0 / 超厚墙压在上限 3.00 / 坐标约定自检
- 请实测（看物理声效[M7] 那行）：
  · 一格厚石头墙 → 遮挡累积≈1.000 实心格≥1 判定挡≥1 直通截止≈0.011（应明显发闷）
  · 门关着 → ≈0.440 / ≈0.138；门打开 → 0.000 / 1.000
  · 若还是全 0：把日志发我，关键看 实心格（=0 说明路径上真没实体）
- 老规矩：只作用于我们自己的声源；原版唱片与其它声音不受影响；出错自动回退，出声优先 ✓
0.12.7 —— 修「门关着和开着遮挡一样」+ 顺手加固刺声（⚠ 已作废，请用 0.12.8）

- **修好「一扇关着的门听不出闷」**（本次重点，两个真原因）：
  · 旧规则"8 条偏移射线里 3 条通透就把遮挡砍掉 85%" → 关着的门只剩 15% → 等于没挂滤波器；
    现在**只有大多数通路都通透（默认 6/8）才放宽，且最多削掉 40%**，达不到门槛一分不放宽 ✓
  · 关着的门自己也被算小了（既不是"不透明"又是"非完整方块"，基础 0.55 只剩 0.22）；
    现在改成**射线精确命中碰撞形状**才算挡：关着的门 = 0.44（约 -17 dB 高频），
    **开着的门 = 0（完全透亮）**，楼梯/栅栏的缝也不再被当成实心格子 ✓
- 门关 vs 门开的高频差距 **8.6 dB → 17.2 dB**；石头墙 -39 dB / 玻璃 -7.8 dB / 木板 -21.5 dB
  这三档与 0.12.6 完全一致
- 配置界面第 2 节：「漏音通路数」默认 3 → **6**，**新增**「漏音放宽上限」（默认 0.40）
- **刺声顺手加固**（不改架构）：播放期间不再改 EFX 接线（只改数值）；直通+发送做能量预算
  避免相加削顶；参数每 3 刻才写一次、阈值加大；关开关时先把参数平滑到直通再摘；
  DSP 兜底链路全程接通（不再把滤波器状态清 0 —— 那正好会产生一个阶跃）
- **新增诊断**：打开「调试日志」后，参数一次跳变超过阈值会打一行
  `物理声效·参数阶跃: …`（最多 1 秒一条）；起播 1/5 秒那两行带上**缓冲剩余空间 / 欠载次数**
- 请实测：门关着应明显闷、门打开应明显透亮；数字核对看 `物理声效[M7]:` 那行的
  `遮挡累积 / 放宽 / 直通截止(GAINHF)`（门开 0.000/0.000/1.000，门关 ≈0.44/0.000/0.138）
- 老规矩：只作用于我们自己的声源；原版唱片与其它声音不受影响；出错自动回退，出声优先 ✓
0.12.6 —— 物理声效调参：隔墙"变闷"明显加强 + 材质探针

- **隔墙更闷**：闷度系数 3.0 → 4.5，并且修掉了把截止顶回去的开阔度下限。
  一层石头墙后面**实际下发**的高频截止 0.19 → **0.011**（约 -14 dB → -39 dB，高频几乎全砍），
  一耳朵能听出来 ✓（以前"一层墙"和"两层墙"下发的是同一个数，加厚完全听不出）
- **修掉两个"不够明显"的真原因**：
  · 以前算完遮挡后又被"开阔空间"修正顶回去（下限 ≈0.19）→ 现在遮挡达到 0.6 时该修正一律失效；
  · 以前 8 条偏移射线"取最小值"，一条缝就把遮挡抹平 → 现在改成**数通路**：
    要 **3 条**以上通透射线才明显放宽，且最多只能把遮挡降到原值的 15% ✓
- **总增益也跟着降**（不只砍高频）：直通增益 截止^0.1 → 截止^0.2，隔一层石头墙总音量也掉到 ≈0.41
- **三档材质拉开**：石头（最闷 0.011）/ 木板（中间 0.084）/ 玻璃（只轻微闷 0.41）现在能明确分辨 ✓
- **强度旋钮真正有用**：以前只调"余响"，现在**同时**调"闷度 + 余响"；
  **0 = 等同关闭**、1 = 默认、**2 = 非常激进** ✓
- **混响更明显**：发送基准 ×1.6、默认衰减时间加长、兜底反射率 0.40 → 0.60
- **新增「材质探针」诊断**（打开"调试日志"后生效）：每轮把真正命中的方块打一行，例如
  `材质探针: minecraft:stone → 遮挡=1.00 反射率=0.60 吸声=0.45（来源=声音组 STONE(石头)）`；
  来源写"默认值"就说明材质表退化了。开局还会打一次"材质表自检" ✓
- 配置界面第 2 节新增「隔墙闷度 k」「漏音通路数」两行
- 老规矩：只作用于我们自己的声源；原版唱片与其它声音不受影响；出错自动回退，出声优先 ✓
0.12.5 ~ 0.12.1 —— 唱片机物理声效（真混响 + 材质遮挡）

- **延迟**：隔墙/拆墙的"闷 ↔ 亮"现在是**瞬间**的（最多 1 刻 = 50ms）
  以前是自己在家算，参数跟着音频块走，所以拆了墙还要闷好几秒；现在直接写进
  Minecraft 音频引擎（OpenAL EFX），下一个混音块就生效 ✓
- **材质**：木板墙 / 石头墙 / 玻璃 / 羊毛 / 水 听感**各不相同**（沿视线逐格累加遮挡）✓
- **余响**：从唱片机朝四周发 32 条射线、每条最多 4 次反弹 → 4 段延迟混响
  大洞穴/大厅尾巴长，小房间短促，铺了羊毛的房间更干 ✓
- **方向**：直通被挡住时，声音从**反射来的方向**绕过来，不再像从墙里穿出来 ✓
- **水下**：潜进水里明显变闷、变小 ✓
- **配置界面**：按 K → 第 2 节「物理声效」（总开关/强度/精度/严格遮挡/方向性/调试日志），
  最后一行会直接告诉你"EFX 可不可用" ✓
- **绝不误伤**：只作用于我们自己的那条声源，原版唱片与其它声音一个字都不动 ✓
- **自动兜底**：不支持 EFX 的设备会退回老的自研 DSP，日志里写明原因 ✓
- ⚠ 若同时装了「物理声效重制版」：它也会给所有声音挂遮挡滤波，测本 Mod 时
  建议先禁用它（不影响能不能用，只影响听感干净程度）
0.9.9 / 0.9.8 —— 修好"玩一会儿就听不见、对方听到原版"

- **根因**：客户端过去只在"通道未就绪"时才向服务端中继续报，而"就绪"取决于"最近收到过应答"。
  应答一过期就出现一段**一个通道都没有**的窗口（日志实测 `udp=0, relay=0, chat=0`）——
  恰好在这段窗口里放碟 → 同步消息发不出去 → **跟随方**只能听到原版唱片声 ✓
  而且续报有 20 次上限（每 3 秒一次）→ **约 7 分钟后就静默失效**，这正是"过了一会"的来源 ✓
- **修法**（三处，全在客户端）：
  - 中继应答有效期 60 秒 → **10 分钟**
  - 收到应答就**重置**续报计数（不再撞上限后停摆）
  - **无论是否就绪，每 20 秒续报一次**（原来只在未就绪时补报）
- **服务端不用动** ✓（服务端组件自 0.4.4 起一行未改，协议已冻结）
- 对应的现象：跟随方听到原版、时好时坏、退房重进有时恢复 —— 现在都应消失 ✓
0.9.6 / 0.9.5 / 0.9.4 —— 插入瞬间的体验 + 令牌可视化

- **修好**：有时插入唱片会先响一下**原版唱片声**，几秒后才切成网易云 ✓
  原因：会话要等"查歌名 + 换地址"完成才登记，而那 1~3 秒里别人来问"谁在放什么"，
  我们这边"看起来什么都没有" → 对方按设计补放了原版声。
  现在改用**右键那一刻就存在的占位标记**回答询问（CLAIM："这块归我，先别放原版"），
  并把"无人认领"的等待窗口从 0.3 秒放宽到 2 秒 —— 那几秒原版声没有了 ✓
- **新增**：配置界面第 2 节多了「**解析服务令牌**」一栏 ✓
  - 以前令牌只能改 JSON，或塞在地址里（界面看不到 ✗）→ 现在**看得见、改得动** ✓
  - 令牌轮换时：服务器改一下 → 大家在界面粘新令牌 → 保存 ✓（不用换 jar）
- **整理**：地址与令牌统一成"地址一栏 + 令牌一栏"（地址里不再夹令牌）✓
0.9.3 —— 单人 / 局域网也能解除唱片时长限制

- **修好**：附加组件 `clouddisc-jukeboxlib` 之前**只在独立服务器上生效** ——
  单人游戏、或你自己开房（局域网）时完全用不上 ✗
  原因：它被标成了"只对服务端应用"，而**单人/局域网的服务端是跑在你客户端进程里的** → 现已改为**两端都应用** ✓
- 现在的适用范围：
  - **单人 / 你开房**：自己装上就用 ✓（连进来的朋友**哪怕没装 Mod** 也听得到完整一首 ✓）
  - **别人的服务器**：需要**服主**装（客户端装没用 —— "放完了吗"的判断在服务端跑）
- **实测通过**：用游戏里**最短的唱片**放一首 4 分多钟的歌 → 完整播完 ✓；**拔碟立刻停** ✓；换碟正常 ✓
- 附加组件版本：**1.0.1**（旧的 1.0.0 请删掉，两个同时放会冲突）
0.9.2 / 0.9.1 / 0.9.0 —— 长曲与"受唱片时长限制"这件事

- **修好**：歌比原版唱片短时，会准确停在**真实结尾**（以前会提前约 3.5 秒断掉 —— 那是拿"已交给音频引擎的字节数"当进度造成的假象）
- **新增（可选）**：**服务端附加组件** `clouddisc-jukeboxlib`
  - 服主把它放进服务端 `mods/`，**长歌就不再被原版唱片时长掐断** ✓（所有玩家都受益，连没装 Mod 的人也听得到完整的一首）
  - 服务器上其他人用**原版唱片完全不受影响** ✓（只对自定义名以 `@` 开头的唱片生效）
  - 不装它也照常工作 —— 只是长歌会被唱片时长限制
- **回归干净行为**：音乐 Mod 不再去猜"这次停止是自然放完还是玩家拔碟"
  → 原版说停就停（**拔碟即停 ✓ 换碟正常 ✓**），不再出现"停不下来 / 换不了碟"
- **兼容性**：`fabricloader >= 0.15.0` —— 同一个 jar 在客户端（0.16.14）与服务端（0.15.11）都能加载
