## 4. 服务端（解析服务）详解

**位置**：`39.105.75.111:8787`，systemd 单元 `clouddisc-resolver`，代码 `/opt/clouddisc-resolver/resolver.py`，令牌文件 `/etc/clouddisc-resolver/token`（请求头 `X-Token` 或 `?token=`）。
**上游**：`http://127.0.0.1:3300`（NeteaseCloudMusicApi 4.32.0，systemd `netease-api`）。

### 路由

| 路由 | 参数 | 说明 |
|---|---|---|
| `/health` | — | 活着即 `{"ok":true,"ts":…}`（不需要令牌） |
| `/song/{id}` | — | 解析成 `{title,url,durationMs}`；`url` 可能是 CDN 直链，也可能是本机 `/stream/{id}` |
| `/stream/{id}` | — | 音频流原样转发（不落盘） |
| `/search` | `keywords`、`type` 或 **`types=a,b,c`**、`limit` | 返回精简 JSON：`{"ok":true,"types":[...],"items":[{"kind","id","name","artist","album","cover","durationMs","radio","radioId"}]}` |

`type` 约定：**1 单曲 / 2000 声音（播客单集）/ 1009 电台（整档）**。
`/search` 内部：先打 `/cloudsearch`，空结果再回退旧 `/search`；两者结构都要能解析（`result.songs/albums/djRadios` 与新版 **`data.resources[].resourceId/uiElement.mainTitle.title`**）。响应里带 `codes` 便于排障。

### `resolve()` 的重要语义（别改坏）

`resolve(song_id)` **先按歌曲**，失败则 `resolve_program()`：① `/dj/program/detail?id=` 当节目单集 ② `/dj/program?rid=&limit=1` 当**整档电台**取第一期。
⇒ 因此 **@数字 id 天然同时支持单曲 / 声音 / 电台**，不需要任何前缀 ✓（曾计划加 `radio:` 前缀，实测没必要）

### 怎么改、怎么部署

1. 本地写脚本 → `powershell -NoProfile -File _tools\ssh-run.ps1 -CommandFile _tools\remote\xxx.sh`
   ✗ 该脚本在**当前会话**会因环境变量大小写重复（`NO_PROXY`/`no_proxy`）让 `Start-Process` 报 key 冲突而失败。
   ✅ 可用的替代（本会话实际用法）：
   ```powershell
   $pw = (Select-String -Path "云服务器酒馆-聊天记录.md" -Pattern '密码：(\S+)' -Encoding UTF8 | Select-Object -First 1).Matches[0].Groups[1].Value
   $ask = Join-Path $env:TEMP 'askpass.cmd'
   [System.IO.File]::WriteAllText($ask, '@echo ' + $pw, (New-Object System.Text.ASCIIEncoding))
   $env:SSH_ASKPASS = $ask; $env:SSH_ASKPASS_REQUIRE = 'force'; $env:DISPLAY = 'localhost:0'
   Get-Content <script.sh> -Raw | & ssh -o StrictHostKeyChecking=accept-new -o PreferredAuthentications=password `
       -o PubkeyAuthentication=no -o NumberOfPasswordPrompts=1 -o ConnectTimeout=15 root@39.105.75.111 "tr -d '\r' | bash -s"
   ```
   **必须带 `tr -d '\r'`** ✓：Windows OpenSSH 会把 stdin 的 LF 转成 CRLF，脚本里会出现 `$'echo\r'` 这类诡异报错。
2. 改 python 时：先 `cp` 一份 `resolver.py.bakN-时间戳` → 改 → `python3 -m py_compile` → `systemctl restart clouddisc-resolver` → `curl` 自检。
3. 脚本里**尽量不写中文**、**不要用括号出现在 echo 里**、heredoc 用唯一的标记名（嵌套 heredoc 会截断）。
4. 改完把 `resolver.py` 拉回仓库 `_serverside/resolver.py` 存档 ✓。

## 6. 踩过的坑（**最重要的一节**，按严重度排）

### 6.1 一个 `@Shadow` 解析失败 ⇒ **整个 mixin 被拒**，而且**不报崩溃、功能静默消失**
实测日志：`Mixin apply for mod clouddisc failed … @Shadow method addRenderableWidget(GuiEventListener) was not located in the target class`。
⇒ 铁砧按钮和提示全都没了，但游戏照常跑。
**因此每个 mixin 都要在启动自检里验一遍**（`CloudDiscClient` 里已有三项：Jukebox/生物渲染/铁砧选歌，都是反射查方法名）。

### 6.2 26.2 的 `addRenderableWidget` 是**泛型受保护方法**，`@Shadow` 认不出
```java
protected <T extends GuiEventListener & Renderable & NarratableEntry> T addRenderableWidget(T)
```
`@Shadow` 声明它会报 "was not located"。✅ 改用**反射**在 `AnvilScreen` 的父类链上按名字找并 invoke（擦除参数是 `GuiEventListener`，`Button` 实现了它）。
同理 `Screens.getButtons(Screen)`（Fabric screen-api）在这个 Loom 配置下**编译期解析不到** ✗，别用。

### 6.3 `EditBox.setValue()` **不触发 responder** ⇒ 改名不生效
只设输入框，服务端**收不到**改名请求 ⇒ 结果槽不重算 ⇒ 拿到的还是旧名字（用户实测"选好了名字没改"）。
✅ 必须走原版链路：反射调 `AnvilScreen.onNameChanged(String)`（私有），它会更新菜单并发包；再兜底 `AnvilMenu.setItemName`。

### 6.4 界面重建的时序：选歌界面**还开着**时写铁砧的控件会被冲掉
返回铁砧时 MC 会重新 `init` 那个界面 ⇒ 改名框是**新建的对象** ⇒ 之前写进去的值丢了。
✅ 现在：选歌回调只记 `clouddisc$pending`，回到铁砧后在 `subInit` / `containerTick` 里落地（`clouddisc$applyPending()`），日志会打「铁砧回填落地 … 改名框现在=…」。

### 6.5 铁砧按钮应该跟着**输入槽**走
没放唱片时不显示：`containerTick` 里 `anvil.getSlot(AnvilMenu.INPUT_SLOT).getItem().isEmpty()` 决定 `button.visible`。

### 6.6 Valve「房间/门道」模型**曾经完全没生效**
`floodAir` 里 `if (d >= 32) continue` + 调用处 cap `2200` ⇒ 距离一远/要绕行，两端泛洪碰不上 ⇒ `pathLen = -1` ⇒ 永远走"只能穿墙"分支。
✅ 已改：深度 **96**、cap **8000**、`pathLen` 每 **5 刻**算一次（缓存进 `State`）。
用户要的"砌一堵墙但上方透气 ⇒ 不该闷"就是这条在管。

### 6.7 遮挡被压到 ~0 时，混响会**反馈自激炸耳**
`sendGain` 原来能到 `1.0`。✅ 加 `SEND_CAP = 0.35f`。任何"把 occ 压低"的新规则都必须保留这个上限。

### 6.8 搜索**不能客户端直连网易云**
`https://music.163.com/api/search/get/web` 返回的是 `{"result":"<hex>"}`（**加密**）✗；`type=2000` 还可能直接 `{"code":400}` ✗。
✅ 只能走解析服务；`type=2000` 走的是**旧 `/search`**，返回结构是 **`{"data":{"resources":[{"resourceId":…,"uiElement":{"mainTitle":{"title":"声音: …"}}}]}}`**，标题里带「声音: 」前缀（客户端再剥一次）。
歌词 `https://music.163.com/api/song/lyric?id=` 是**明文** ✓，可以客户端直连。

### 6.9 音频这块的雷（**已经全部回滚，别再自己加**）
- HRTF（MC「定向音频」）会**绕过 EFX** ⇒ 物理声效失效；要用 DSP 兜底必须保证"同一时刻只有一个处理器"，否则 EFX+DSP 双跑 ⇒ 混响叠加炸掉。
- `filterMono` 里曾有 `if (EfxEngine.isAvailable()) return;` ⇒ 强制 DSP 也不跑。
- `AL_SOURCE_RADIUS` 在没有该扩展的设备上硬设 ⇒ `AL_INVALID_OPERATION(40961)` 刷屏并污染错误状态 ⇒ 连带 EFX 失效。
⇒ 这些改动都在分支 `audio-hrtf-experiments-1018-1438` 里存档；**主线（main）不包含**。想捡必须一项一项来、每项都带开关、每项都实测。

### 6.10 PowerShell 改 Java 文件的坑（本会话最浪费时间的地方）
- 文件是 **LF**，但 here-string 里写的是 **CRLF** ⇒ `Replace` **永远匹配不上**（静默不改，白折腾）。要么按**行索引**改，要么把锚点也 `-replace "`r`n","`n"`。
- 多行字符串里出现中文引号 `"…"` 会被 PS 当字符串结束 ⇒ 语法错；**用「」**。
- `@Unique` 连续两行 ⇒ 编译报 `Unique is not a repeatable annotation interface`。
- `$a` 与 `$A` 是同一个变量（PS 不区分大小写）⇒ 路径被覆盖成 "Illegal characters in path"。
- `Set-Content`/`>` 会写 UTF-16 或改行尾 ⇒ 源码被写坏；**用 `[System.IO.File]::WriteAllText(path, text, utf8NoBom)`**，或者干脆用 `write`/`edit` 工具。
- ⚠️ 结论：**优先用 write/edit 工具写整份文件**，比在 PowerShell 里做多行替换安全得多。

### 6.11 Gradle 的假故障
`Could not create service of type FileLockContentionHandler … BindException: Address already in use` ⇒ 与代码无关，`--stop` + 重试（常常第 3 次就好）。构建失败时**先看是不是这个**，别改代码。

### 6.12 启动器的"错误报告"不一定是崩溃
PCL 的 zip 里常见：`Pack declares support for format 0`（旧资源包 ✗ 不是我们的）、`voxy provides a broken implementation of ModMenuApi`（voxy ✗）、`Client shutdown from post-main`（**关游戏时的看门狗** ✗ 不是崩溃）。
